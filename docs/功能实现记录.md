## 2026-09-08：Linux epoll Reactor 服务端

### 已实现

- 将 Windows“一连接一线程”服务端迁移为 Linux `epoll` Reactor。
- 监听 socket 与客户端 socket 均使用非阻塞模式。
- 使用 `EPOLLET` 边沿触发处理连接、读事件和写事件。
- 使用“4 字节网络序包长 + 协议体”的消息帧格式。
- 为每个连接维护输入缓存，正确处理 TCP 半包与粘包。
- 为每个连接维护输出队列，支持非阻塞部分发送和 `EPOLLOUT` 续传。
- 使用固定业务线程池处理完整协议包，避免数据库操作阻塞 I/O 线程。
- 使用 `eventfd` 将业务线程的发送请求唤醒并交回 Reactor 线程处理。
- 保证同一连接内的协议包顺序执行，不同连接可并行处理。
- 单连接输出积压超过 8 MiB 时主动断开，防止慢客户端耗尽内存。
- 支持 `SIGINT`、`SIGTERM` 信号触发优雅退出。

### 主要文件

- `net/EpollTcpServer.cpp`

## 2026-09-13：心跳检测、超时断开与自动重连

### 已实现

- 新增心跳请求与心跳回复协议。
- Qt 客户端使用 `QTimer` 每 30 秒发送一次心跳。
- 服务端收到任意数据时刷新连接最近活跃时间。
- 服务端通过 `timerfd` 每 10 秒扫描一次连接。
- 连接连续 90 秒无数据时由 Reactor 主动断开，并执行用户离线清理。
- `timerfd` 与监听 socket、客户端 socket、`eventfd` 统一注册到 `epoll`。
- 客户端断线后每 3 秒尝试重新连接。
- 重连成功后自动恢复心跳，并使用本次进程中最近一次成功登录的凭据恢复会话。
- 客户端增加发送互斥，防止心跳与聊天消息交叉写入 TCP 字节流。

## 2026-09-13：MySQL 连接池与业务队列限流

### 已实现

- 将单个 MySQL 连接加全局互斥锁的串行模型改为固定容量连接池。
- 查询、更新、插入、事务和转义操作分别独占连接，多个业务线程可以并行访问数据库。
- 使用 RAII 连接租约，在成功、失败和提前返回路径上自动归还连接。
- 启动阶段建立全部数据库连接；任意连接失败时不开放监听端口。
- 借出连接时执行健康检查，断线后尝试自动重连并补足池容量。
- 不依赖已弃用的 `MYSQL_OPT_RECONNECT`，由连接池在 `mysql_ping` 失败后显式重建连接。
- 获取连接最多等待 3 秒，避免数据库拥塞时业务线程无限阻塞。
- 退出时等待在途 SQL 完成，再关闭连接池。
- 业务任务队列增加容量限制，默认最多保留 10000 个未完成协议包。
- 队列达到上限时拒绝新任务并关闭过载连接，避免突发流量耗尽内存。
- 断开连接时同步清理并统计该连接尚未开始的等待任务。
- 数据库初始化完成后才启动网络监听，消除启动阶段的请求竞态。
- 新增 `IM_DB_POOL_SIZE`、`IM_WORKER_THREADS` 和 `IM_MAX_PENDING_JOBS` 环境变量。

## 2026-09-13：唯一连接编号与双向在线映射

### 已实现

- Reactor 每次 `accept` 都生成单调递增且不复用的 `connectionId`。
- `epoll` 内部继续使用 fd 处理 I/O，业务线程、协议回调和发送请求只使用 `connectionId`。
- Reactor 维护 `connectionId → fd` 映射，实际发送前重新解析并验证连接仍然存在。
- 连接关闭后立即移除编号映射，延迟到达的旧发送请求会被安全丢弃。
- 业务任务按 `connectionId` 保证连接内顺序，fd 被操作系统复用后属于独立任务序列。
- 断线事件作为空标记排在该连接当前业务任务之后执行，并丢弃尚未开始的普通协议。
- 断线数据库查询与好友通知移入工作线程，不再阻塞 Reactor I/O 循环。
- 核心层同时维护 `userId → connectionId` 与 `connectionId → userId` 双向映射。
- 连接断开时通过反向映射 O(1) 定位用户，不再遍历全部在线用户。
- 同一账号重复登录时，新连接替换旧连接认证；旧连接后续任务不能冒用该用户身份。
- 旧连接的断线回调只删除仍指向自身的记录，不会误删新的登录会话。

## 2026-09-14：密码哈希升级与登录失败限流

### 已实现

- 新注册密码使用16字节加密随机盐和120000轮PBKDF2-HMAC-SHA256，不再直接保存单次SHA-256结果。
- 密码编码同时保存算法、迭代次数、盐和派生结果，字段长度扩展为VARCHAR(255)。
- 旧版64位SHA-256密码保持兼容，首次成功登录时自动生成随机盐并透明升级，无需用户重置密码。
- 密码比较使用OpenSSL常量时间比较函数，减少时序信息泄露。
- 注册和登录处理函数退出时使用OpenSSL显式擦除网络包中的明文密码缓冲区。
- 连续5次凭据错误后，将手机号SHA-256摘要限流60秒；5分钟无失败后重新计算失败窗口。
- 限流表最多保留4096项并淘汰长期未访问项，避免随机账号攻击造成内存无限增长。
- 限流日志只包含连接ID和剩余秒数，不记录手机号、密码或账号摘要。
- Prometheus新增 `im_server_rate_limited_logins_total` 指标，Grafana异常面板新增登录限流速率。
- 一键集成测试新增连续失败和第六次请求被限流的自动验证。
- 测试数据准备脚本不再覆盖已有账号密码，避免每轮压测将PBKDF2降回旧格式并把自动升级成本混入性能数据。
- 一键脚本在业务测试后自动查询数据库，要求4个专用账号均为PBKDF2格式且哈希值各不相同，从而验证透明升级和随机盐，而不输出实际密码哈希。

### 验证方法

1. 旧数据库先执行 `mysql -u imserver -p imdb < database/migrate_password_security.sql`。
2. 使用旧SHA-256账号成功登录后，数据库密码应以 `pbkdf2_sha256$` 开头，并产生 `password_hash_upgraded` 日志。
3. 新注册账号的密码字段应直接以 `pbkdf2_sha256$120000$` 开头，且相同密码的不同用户编码结果不同。
4. 对同一不存在账号连续尝试6次错误登录，第六次应产生 `login_rate_limited`，指标累计值增加1。
5. 一键集成报告的 `login_rate_limit` 步骤应为 `true`。
6. VMware Linux完整集成测试已通过，`login_rate_limit=true`；密码升级后的登录、消息持久化、离线补发、ACK、历史分页和好友申请链路均未发生回归。
7. 一键脚本第三阶段已在MySQL真实数据上通过：4个专用账号均使用PBKDF2编码，`COUNT(DISTINCT password)=4`，证明每个账号使用独立随机盐。
